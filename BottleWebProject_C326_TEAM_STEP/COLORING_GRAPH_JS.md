# Граф конфликтов: как работает JS-генерация

Файл: `static/scripts/coloring_practice.js`
Библиотека: `vis-network` (`static/scripts/vis-network.min.js`)

---

## Общая схема

Весь код обёрнут в IIFE `(function () { ... })()`, чтобы не засорять глобальную область видимости.

При загрузке страницы вызывается `refreshEditor()`, который в конце вызывает `drawGraph()` — так граф строится сразу при открытии, без каких-либо действий пользователя.

Единственный объект `graphNetwork` (тип `vis.Network`) хранится в замыкании. При каждом перерисовывании он **не пересоздаётся** — вызываются `setOptions` + `setData`, что сохраняет позиции узлов между редактированиями.

---

## Откуда берутся данные

### Вершины (`getSubjectItems`)

Читает строки таблицы `[data-subject-body]`. Из каждой строки берёт:

- `input.subject-name` → имя дисциплины;
- `input[name="teacher[]"]` → преподаватель;
- атрибут `data-color` на `<tr>` → номер смены (0 если не рассчитан).

Дубликаты по имени пропускаются. Цвет смены устанавливается сервером при рендере шаблона; при ручном редактировании имени — атрибут `data-color` сбрасывается в `""`, и вершина возвращается к нейтральному виду.

### Рёбра (`getConflicts`)

Читает элементы `.conflict-item` из `[data-conflict-list]`. Каждый элемент хранит атрибуты `data-conflict-from` и `data-conflict-to`.

## Построение узлов

Для каждой дисциплины создаётся объект узла:

```js
{
    id: subject.name,          // имя — уникальный ID
    label: graphLabel(name),   // имя, разбитое на строки ≤16 символов
    title: teacher,            // всплывающая подсказка при наведении
    shape: 'box',
    color: colorByShift(shift),
    font: { color: fontColor(shift), ... },
    ...nodeView                // размеры зависят от количества вершин
}
```

### Перенос длинных названий (`graphLabel`)

Слова разбиваются по пробелам. Если добавление следующего слова превысит **16 символов** в строке — начинается новая строка. Строки объединяются через `\n`; `vis-network` сам рендерит многострочные метки.

## Цвета вершин

### Палитра смен (`shiftColors`)

8 цветов, используются по кругу для смен 1–8+ через `(shift - 1) % 8`:

| Смена | Цвет      | HEX       |
|-------|-----------|-----------|
| 1     | красный   | `#c94d57` |
| 2     | зелёный   | `#3a9d66` |
| 3     | синий     | `#2e86ab` |
| 4     | жёлтый    | `#c28f2c` |
| 5     | фиолетовый| `#6f5aa8` |
| 6     | бирюзовый | `#2f8f83` |
| 7     | оранжевый | `#d46a4c` |
| 8     | серо-синий| `#4a6fa5` |

### Нейтральный вид (смена не рассчитана)

- фон: белый `#ffffff`, рамка: `#2e86ab`;
- при наведении фон `#e8eef5`;
- текст тёмный `#1d3557`;
- обводка текста `strokeWidth: 3` (`#ffffff`) — чтобы метка читалась на любом фоне.

### Вид после расчёта

- фон: цвет из палитры, рамка: белая, толщина рамки `3` (у нейтральных — `2`);
- обводка текста убирается (`strokeWidth: 0`);
- цвет текста определяется функцией `fontColor`: для смен 2, 3, 5, 6, 7, 8 — белый; для смен 1 и 4 — тёмный `#1d3557` (светлые цвета фона).

## Построение рёбер

Для каждого конфликта создаётся ребро:

```js
{
    id: [from, to].sort().join('::'),   // ключ из отсортированных имён
    from, to,
    color: { color: '#8fa1b4', highlight: '#c94d57' },
    width: 2,
    selectionWidth: 4,
    smooth: { type: 'dynamic', roundness: 0.25 }
}
```

Дубликаты (одно и то же ребро в обоих направлениях) отфильтровываются через объект `usedEdges` — ключ строится из отсортированных имён, поэтому `A::B` и `B::A` дают один ключ.

Рёбра, у которых хотя бы одна сторона не существует как вершина или `from === to`, пропускаются.

## Адаптивные размеры узлов (`graphNodeView`)

Размеры шрифта, отступов и физических параметров подбираются по количеству вершин:

| Вершин | Шрифт | minWidth | maxWidth | distance | spring |
|--------|-------|----------|----------|----------|--------|
| ≤ 5    | 28px  | 240      | 380      | 360      | 250    |
| ≤ 10   | 23px  | 190      | 320      | 290      | 210    |
| ≤ 16   | 20px  | 160      | 280      | 230      | 170    |
| > 16   | 18px  | 140      | 250      | 200      | 150    |

`distance` и `spring` передаются в физический движок. При большом числе вершин узлы мельчают и держатся ближе друг к другу — это предотвращает выход графа за экран.

## Физика и размещение

Используется решатель `repulsion` (отталкивание):

```js
physics: {
    solver: 'repulsion',
    stabilization: { iterations: 220, updateInterval: 20 },
    repulsion: {
        nodeDistance: ...,    // из graphNodeView
        centralGravity: 0.16,
        springLength: ...,    // из graphNodeView
        springConstant: 0.09,
        damping: 0.12
    }
}
```

`randomSeed: 7` фиксирует начальные позиции — при одинаковых данных граф выглядит одинаково.

Симуляция запускается на `220` итераций. По окончании срабатывает событие `stabilizationIterationsDone`, вызывающее `focusGraph`. Дополнительно запускается `setTimeout(focusGraph, 1300)` — страховка на случай, если событие не придёт.

## Центрирование и масштабирование (`focusGraph` → `graphView`)

1. `graphNetwork.fit()` — автоматически вписывает все вершины в область просмотра.
2. `getViewPosition()` — запоминает полученный центр.
3. `getScale()` — запоминает масштаб от `fit()`, но ограничивает его сверху значением из таблицы `graphScale` × 2.1.
4. `moveTo({ position, scale, animation })` — плавно перемещает камеру за `350 мс` с `easeInOutQuad`.

### Таблица масштабов (`graphScale`)

| Вершин | Начальный scale |
|--------|-----------------|
| ≤ 5    | 0.54            |
| ≤ 10   | 0.50            |
| ≤ 16   | 0.44            |
| > 16   | 0.36            |

Чем больше вершин, тем дальше отъезжает камера.

### Геометрический центр (`graphCenter`)

Берёт `getPositions()` — словарь `{id: {x, y}}` всех вершин. Находит `min/max` по X и Y, возвращает середину bounding box. Это нужно потому, что `fit()` может сработать нестабильно при первом рендере — центр вычисляется как запасной вариант.

## Изменение размера canvas (`resizeGraphCanvas`)

`vis-network` рисует в `<canvas>` внутри контейнера. Если CSS задаёт `height: 100%`, canvas может остаться нулевым до первой перерисовки. Функция явно:

1. Берёт `clientHeight`/`offsetHeight` контейнера (минимум 560px).
2. Устанавливает `style.height` на контейнере.
3. Вызывает `network.setSize('100%', height + 'px')`.
4. Напрямую ставит `canvas.width` / `canvas.height` (минимум 900px по ширине).
5. Вызывает `network.redraw()`.

## Реакция на действия пользователя

| Событие | Что вызывается |
|---------|----------------|
| Добавление дисциплины | `addSubject` → `refreshEditor` → `drawGraph` |
| Удаление дисциплины | `refreshEditor` → `drawGraph`; связанные конфликты удаляются |
| Редактирование имени дисциплины | `refreshEditor` → обновляет выпадающие списки, удаляет устаревшие конфликты, `drawGraph` |
| Редактирование преподавателя | `drawGraph` (tooltip обновляется, `data-color` не меняется) |
| Добавление конфликта | `addConflict` → `drawGraph` |
| Удаление конфликта | `drawGraph` |
| Кнопка «Уместить» | `graphView` → `moveTo` с анимацией 300мс |
| Кнопка «Расположить» | `physics: enabled` → `stabilize(180)` → через 300мс `focusGraph` |
| Resize окна | `focusGraph` |

---

## Как обновляется граф при расчёте с сервера

Сервер отдаёт страницу заново. Шаблон рендерит строки таблицы с атрибутом `data-color="{{ цвет_смены }}"`. При инициализации JS читает эти атрибуты через `getSubjectItems` и передаёт цвет в `colorByShift` — вершины сразу отображаются в цвете смены без дополнительных запросов.
