# Четвертый вариант: раскраска графа

## Назначение

Четвертый вариант решает задачу распределения дисциплин по сменам методом раскраски графа.
Дисциплины считаются вершинами графа, а конфликты между дисциплинами - ребрами.
Если между двумя дисциплинами есть конфликт, они не должны попасть в одну смену.

## Где находится код

- `algorithms/coloring.py` - основная логика алгоритма, валидация, импорт, генерация и подготовка данных для экспорта.
- `routes.py` - маршрут `/coloring/practice`, обработка действий формы (расчёт, генерация, импорт, экспорт).
- `views/coloring_practice.tpl` - страница практики четвертого варианта.
- `static/scripts/coloring_practice.js` - работа таблиц, конфликтов и интерактивного графа на странице.
- `static/content/coloring_theory.css` - стили страницы теории и практики четвертого варианта.
- `data/coloring_history.json` - история выполненных расчётов, дополняется при каждом расчёте.
- `tests/test_coloring.py` - unit-тесты основной логики.
- `tests/test_coloring_ui.py` - Selenium/UI-проверка страницы практики.
- `COLORING_REQUIREMENTS_CHECK.md` - проверка соответствия требованиям.
- `COLORING_TEST_REPORT.md` - краткий отчет о тестировании.
- `COLORING_CODE_USAGE.md` - описание работы кода и инструкция по использованию страницы.
- `COLORING_SELENIUM_GUIDE.md` - запуск Selenium, написание UI-тестов и сценарии использования.

Каждая функция в `algorithms/coloring.py` и обработчики раскраски в `routes.py` снабжены короткими однострочными комментариями (docstring), описывающими их назначение.

## Ручной ввод данных

На странице практики есть две основные таблицы:

- `Дисциплины` - название дисциплины и преподаватель.
- `Конфликты` - пары дисциплин, которые нельзя ставить в одну смену.

Дисциплины можно добавлять кнопкой `Добавить`, редактировать прямо в таблице и удалять через кнопку `×`.
После изменения названия дисциплины список конфликтов обновляется, а некорректные конфликты удаляются.

Конфликт добавляется выбором двух дисциплин из выпадающих списков. Одинаковые и повторяющиеся конфликты не добавляются.

## Импорт JSON

В блоке `Импорт из JSON` можно загрузить файл с такой структурой:

```json
{
  "subjects": [
    { "name": "Математика", "teacher": "Иванов" },
    { "name": "Физика", "teacher": "Петров" }
  ],
  "conflicts": [
    ["Математика", "Физика"]
  ]
}
```

После импорта данные попадают в те же таблицы, поэтому их можно вручную подредактировать:
добавить дисциплины, изменить преподавателей, добавить или удалить конфликты.

Экспортированный JSON тоже можно загрузить обратно, потому что поля `subjects` и `conflicts` остаются полностью совместимыми с импортом.

## Случайная генерация

В блоке `Случайная генерация` задаются:

- количество дисциплин;
- плотность графа от `0` до `1`.

Генератор создает дисциплины с названиями вида `Дисциплина 1`, `Дисциплина 2` и так далее.
Преподаватели распределяются из небольшого списка фамилий.
Плотность графа управляет количеством случайных конфликтов.

## Просмотр графа

Граф отображается в блоке `Граф конфликтов`.
Вершины - дисциплины, ребра - конфликты.
После расчета вершины окрашиваются по найденным сменам.

Доступны кнопки:

- `Уместить` - возвращает граф в область просмотра.
- `Расположить` - заново запускает авторазмещение графа.

Граф можно двигать и масштабировать мышью.

## Расчет расписания

Кнопка `Рассчитать расписание` отправляет текущие данные на сервер.
Сервер выполняет проверку данных и запускает алгоритм:

1. строит граф конфликтов;
2. сортирует вершины по степени;
3. выполняет жадную раскраску Welsh-Powell;
4. пытается уменьшить количество смен;
5. старается уменьшить количество смен у одного преподавателя;
6. формирует итоговое расписание.

Алгоритм оставлен таким, как указан в задании: жадная раскраска и локальная оптимизация.
В описании результата для отчета корректно писать, что программа строит расписание заданным алгоритмом и уменьшает количество смен в рамках локальной оптимизации.
Полный перебор всех возможных раскрасок не используется, потому что это был бы другой алгоритм.

В результате выводятся:

- количество смен;
- штраф по сменам преподавателей;
- количество конфликтов;
- расписание по сменам;
- смены каждого преподавателя;
- порядок обработки вершин.

Каждый успешный расчёт дописывается в файл истории `data/coloring_history.json`.

## Экспорт результата

После расчета появляется кнопка `Скачать JSON` (действие формы `export_json`).
Она выгружает файл вида `coloring_result_YYYYMMDD_HHMMSS.json`.

Структура файла:

```json
{
  "subjects": [],
  "conflicts": [],
  "result": {
    "algorithm": "Welsh-Powell",
    "num_colors": 0,
    "colors": {},
    "schedule": [],
    "teacher_shifts": [],
    "teacher_cost": 0,
    "order": [],
    "degrees": {}
  }
}
```

Поля `subjects` и `conflicts` нужны для обратного импорта.
Поле `result` хранит готовый расчет и не мешает повторной загрузке файла.

## Unit-тесты

Unit-тесты находятся в `tests/test_coloring.py`.
Они проверяют:

- очистку пробелов во входных данных;
- игнорирование пустых строк;
- ошибки при пустом списке дисциплин;
- ошибки при некорректной строке дисциплины;
- ошибки при пустом названии дисциплины;
- ошибки при пустом преподавателе;
- ошибки при повторяющихся дисциплинах;
- ограничение максимального количества дисциплин;
- ошибки при некорректных конфликтах;
- ошибки при конфликте с неизвестной дисциплиной;
- игнорирование пустых, одинаковых и повторных конфликтов;
- построение неориентированного графа;
- сортировку вершин по степени;
- жадную раскраску;
- случай без конфликтов;
- цепочку конфликтов;
- полный граф;
- расписание по сменам;
- расчет смен преподавателей;
- загрузку корректного JSON;
- ошибки при некорректной структуре JSON;
- игнорирование поля `result` при повторном импорте;
- совместимость экспортированного JSON с импортом;
- случайную генерацию с нулевой и полной плотностью;
- ограничение количества сгенерированных дисциплин;
- ограничение плотности графа;
- независимость копии демонстрационных данных.

Запуск тестов:

```bash
python -m unittest discover -s tests -p "test_*.py"
```

Ожидаемый результат:

```text
Ran 34 tests
OK
```

## Selenium/UI-тесты

UI-проверка находится в `tests/test_coloring_ui.py`.
Она запускает страницу практики в браузере, проверяет основные элементы формы, импорт JSON, ручное редактирование после импорта, расчет результата, граф и случайную генерацию.

Отдельный запуск:

```bash
python -m unittest tests.test_coloring_ui
```

Если Selenium или браузерный драйвер не установлен, UI-тест будет пропущен, а unit-тесты основной логики продолжат выполняться.
