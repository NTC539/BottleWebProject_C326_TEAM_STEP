# Selenium-проверка четвертого варианта

## Что проверяется

Selenium-тесты относятся только к четвертому модулю: странице `/coloring/practice`.

Файл тестов:

```text
tests/test_coloring_ui.py
```

Тесты открывают страницу в браузере, работают с формой так же, как пользователь, и проверяют:

- наличие основных элементов страницы;
- импорт данных из JSON;
- ручное редактирование после импорта;
- добавление конфликта;
- расчет расписания;
- появление результата;
- отображение canvas интерактивного графа;
- случайную генерацию;
- ошибку при избыточном количестве дисциплин.

## Как запустить Selenium-тесты

1. Перейти в папку проекта:

```powershell
cd D:\Development\Projects\BottleWebProject_C326_TEAM_STEP\BottleWebProject_C326_TEAM_STEP
```

2. Установить Selenium, если он еще не установлен:

```powershell
python -m pip install selenium
```

3. Запустить UI-тесты:

```powershell
python -m unittest tests.test_coloring_ui -v
```

4. Запустить все тесты проекта:

```powershell
python -m unittest discover -s tests -p "test_*.py"
```

Selenium-тест сам запускает Bottle-сервер на свободном локальном порту. Отдельно запускать `python app.py` для автотеста не нужно.

Если нужно вручную открыть страницу без теста:

```powershell
python app.py
```

После этого открыть:

```text
http://127.0.0.1:5555/coloring/practice
```

## Если Selenium не запускается

Проверить, установлен ли Selenium:

```powershell
python -c "import selenium; print(selenium.__version__)"
```

Проверить, установлен ли браузер Chrome или Edge.

Selenium 4 обычно сам подбирает драйвер через Selenium Manager. Если браузер не найден или драйвер не подходит, нужно обновить Chrome/Edge или установить подходящий WebDriver вручную.

## Как устроен текущий UI-тест

Тестовый класс:

```python
class ColoringPracticeUiTest(unittest.TestCase):
```

В `setUpClass()` тест:

- выбирает свободный порт;
- запускает `app.py`;
- ждет, пока откроется `/coloring/practice`;
- запускает Chrome в headless-режиме;
- если Chrome недоступен, пробует Edge.

В `tearDownClass()` тест:

- закрывает браузер;
- останавливает Bottle-сервер.

После каждого теста вызывается `tearDown()`, который удаляет из `data/coloring_history.json` тестовые записи, созданные Selenium-сценарием.

## Как писать свои Selenium-тесты

Лучше добавлять новые проверки в `tests/test_coloring_ui.py`, чтобы все UI-тесты четвертого варианта были в одном месте.

Базовый шаблон:

```python
def test_my_new_scenario(self):
    self.driver.get(self.base_url + "/coloring/practice")

    self.driver.find_element(self.By.ID, "newSubjectName").send_keys("Биология")
    self.driver.find_element(self.By.ID, "newSubjectTeacher").send_keys("Иванов")
    self.driver.find_element(self.By.ID, "addSubjectBtn").click()

    self.wait_until(lambda driver: "Биология" in self.subject_values())

    self.driver.find_element(self.By.CSS_SELECTOR, "button[type='submit']").click()
    self.wait_css("#coloring-result")

    self.assertIn("Биология", self.driver.page_source)
```

Рекомендации:

- использовать `self.wait_css(...)` и `self.wait_until(...)`, а не `time.sleep`;
- искать элементы по стабильным `id`, `name`, `data-*` и CSS-селекторам;
- для проверки значений таблицы использовать `self.subject_values()`;
- для проверки количества конфликтов использовать `self.conflict_count()`;
- временные JSON-файлы создавать через `tempfile.NamedTemporaryFile`;
- после сценариев с расчетом очищать тестовую историю через `tearDown()`;
- не проверять чужие страницы и чужие модули в этом файле.

## Проверка избыточных данных

В коде ограничение задано в `algorithms/coloring.py`:

```python
MAX_SUBJECTS = 20
```

Если отправить больше 20 дисциплин, `check_input(...)` добавляет ошибку:

```text
Количество дисциплин не должно превышать 20.
```

Selenium-сценарий `test_too_many_subjects_show_validation_error` создает в форме 21 дисциплину и нажимает кнопку расчета. Ожидаемый результат:

- появляется блок ошибки;
- текст ошибки содержит ограничение `20`;
- блок результата не появляется.

## Что считать успешной проверкой

Успешный запуск Selenium выглядит так:

```text
test_json_import_manual_edit_and_calculation ... ok
test_page_has_required_controls ... ok
test_random_generation_updates_subject_table ... ok
test_too_many_subjects_show_validation_error ... ok

OK
```

При запуске всех тестов количество тестов должно быть больше, потому что вместе с Selenium запускаются unit-тесты основной логики.
